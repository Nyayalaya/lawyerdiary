🎯 WHY THIS CHANGE?
═════════════════════════════════════════════════════════════════════════════

BEFORE (Less Secure):
  ❌ Connection strings hardcoded in config files
  ❌ Risk of exposing production credentials
  ❌ Same connection string for all environments
  ❌ Hard to manage different databases

AFTER (More Secure):
  ✅ Connection strings configured per environment
  ✅ Production credentials never in code
  ✅ Different databases for Dev/Staging/Prod
  ✅ Easy to manage using environment variables
  ✅ Industry standard security practice

🚀 QUICK START (Choose Your Environment)
═════════════════════════════════════════════════════════════════════════════

DEVELOPMENT (5 minutes):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Edit: appsettings.Development.json

   Add PostgreSQL:
   {
     "ConnectionStrings": {
       "Postgres": "server=localhost;port=5432;user id=postgres;password=YOUR_PASSWORD;database=ldms_dev"
     }
   }

   Or SQL Server:
   {
     "ConnectionStrings": {
       "SqlServer": "Server=(localdb)\\MSSQLLocalDB;Database=ldms_dev;TrustServerCertificate=True"
     }
   }

2. Run:
   $ set ASPNETCORE_ENVIRONMENT=Development
   $ dotnet run

3. ✅ Done! Database is configured


STAGING (10 minutes):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Edit: appsettings.Staging.json

   {
     "ConnectionStrings": {
       "Postgres": "server=staging-db.yourdomain.com;port=5432;user id=staging_user;password=STAGING_PASSWORD;database=ldms_staging"
     }
   }

2. Run:
   $ set ASPNETCORE_ENVIRONMENT=Staging
   $ dotnet run

3. ✅ Done! Database is configured


PRODUCTION (15 minutes - SECURE):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

⚠️  NEVER add connection string to appsettings.Production.json

1. Set Environment Variable (Windows):
   $ set ASPNETCORE_ENVIRONMENT=Production
   $ set ConnectionStrings__Postgres=server=prod-db.yourdomain.com;port=5432;user id=prod_user;password=SECURE_PASSWORD;database=ldms_prod

2. Set Environment Variable (Linux/Mac):
   $ export ASPNETCORE_ENVIRONMENT=Production
   $ export ConnectionStrings__Postgres="server=prod-db.yourdomain.com;port=5432;user id=prod_user;password=SECURE_PASSWORD;database=ldms_prod"

3. Run:
   $ dotnet run --configuration Release

4. ✅ Done! Database is secure (not in code files)

🔐 SECURITY BEST PRACTICES
═════════════════════════════════════════════════════════════════════════════

DEVELOPMENT:
  ✓ Connection string in appsettings.Development.json (safe, local)
  ✓ Non-sensitive passwords acceptable
  ✓ Or use User Secrets (even more secure)

STAGING:
  ✓ Connection string in appsettings.Staging.json (careful)
  ✓ Use strong staging passwords
  ✓ Different database from production
  ✓ Or use environment variables

PRODUCTION:
  ✗ NEVER in appsettings.Production.json
  ✓ Use Environment Variables ONLY
  ✓ Use very strong, random password
  ✓ Use dedicated database user (limited privileges)
  ✓ Enable SSL/TLS for database connection
  ✓ Rotate passwords regularly
  ✓ Monitor access logs

📝 CONNECTION STRING EXAMPLES
═════════════════════════════════════════════════════════════════════════════

PostgreSQL (Local - Development):
  server=localhost;port=5432;user id=postgres;password=dev123;database=ldms_dev

PostgreSQL (Remote - Staging):
  server=staging-db.company.com;port=5432;user id=staging_user;password=staging_pass;database=ldms_staging

PostgreSQL (Remote - Production with SSL):
  server=prod-db.company.com;port=5432;user id=prod_user;password=SECURE_PASS;database=ldms_prod;SSL Mode=Require;

SQL Server (Local - Development):
  Server=(localdb)\MSSQLLocalDB;Database=ldms_dev;TrustServerCertificate=True

SQL Server (Remote - Production):
  Server=prod-sql.company.com;Database=ldms_prod;User Id=prod_user;Password=SECURE_PASS;Encrypt=true;

Azure PostgreSQL:
  server=myserver.postgres.database.azure.com;port=5432;user id=username@myserver;password=PASSWORD;database=ldms;SSL Mode=Require;

AWS RDS:
  server=mydb.region.rds.amazonaws.com;port=5432;user id=admin;password=PASSWORD;database=ldms;SSL Mode=Require;

🔧 HOW TO CONFIGURE (Step by Step)
═════════════════════════════════════════════════════════════════════════════

STEP 1: Choose Database Provider
  ☐ PostgreSQL (recommended)
  ☐ SQL Server

STEP 2: Determine Your Database Details
  ☐ Server hostname/IP
  ☐ Port number
  ☐ Username
  ☐ Password
  ☐ Database name

STEP 3: Build Connection String
  PostgreSQL:
    server=HOSTNAME;port=5432;user id=USERNAME;password=PASSWORD;database=DBNAME

  SQL Server:
    Server=HOSTNAME;Database=DBNAME;User Id=USERNAME;Password=PASSWORD;TrustServerCertificate=True

STEP 4: Configure for Your Environment
  Development:  Edit appsettings.Development.json
  Staging:      Edit appsettings.Staging.json
  Production:   Set ConnectionStrings__Postgres environment variable

STEP 5: Test Connection
  $ dotnet run
  Check logs for: "Database connection successful"

🆘 ENVIRONMENT VARIABLE FORMAT
═════════════════════════════════════════════════════════════════════════════

ASP.NET Core converts environment variables to configuration using:
  ` : ` becomes ` __ ` (colon becomes double underscore)

Example:
  Configuration key:     ConnectionStrings:Postgres
  Environment variable:  ConnectionStrings__Postgres

So when setting environment variable for production:
  set ConnectionStrings__Postgres=your-connection-string
  (NOT: set ConnectionStrings:Postgres=...)
